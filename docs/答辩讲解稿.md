## 一、答辩开场白（约 30 秒）

> 各位老师好，我做的项目是《蓉城印象·成都文旅探索网站》，一个以成都为主题的文旅探索网页。
> 项目采用**原生 HTML5 + CSS3 + JavaScript(ES6+)** 完成，没有使用任何前端框架，纯静态结构，可以直接部署到 Gitee Pages 在线访问。
> 接下来我从「项目结构、技术点、功能演示」三个方面来介绍。

## 二、项目介绍（约 1 分钟）

**主题定位**：以「成都」为载体，把「景点推荐 + 美食文化 + 互动留言」串成一条完整的探索链路，体现「文旅」二字。

**技术选型理由**（答辩时的亮点话术）：

1. **原生三件套，零依赖**：不引入 Vue/React 等框架，代码量可控、可读性强，也符合「先夯实基础」的课程要求；
2. **纯静态结构**：没有后端，`localStorage` 承担数据持久化，天然适合 Gitee Pages 等静态托管，无需服务器；
3. **语义化 + 响应式**：标签结构清晰（`header/nav/main/section/footer`），移动端也能正常浏览。

**目录结构**（一句话带过，展示工程规范）：

```
├── index.html       # 页面结构
├── css/style.css    # 样式（变量/布局/响应式）
├── js/main.js       # 交互逻辑
├── images/  pages/  # 预留资源与子页面目录
└── README.md        # 说明文档
```

## 三、技术点讲解（约 1.5 分钟，边讲边对照代码）

按评分点逐一说明，做到「每个技术点都能指出对应代码位置」：

| 评分点 | 技术要点 | 对应代码 |
|---|---|---|
| HTML 语义化 | 用 `<header>/<nav>/<main>/<section>/<footer>` 搭建骨架，语义清晰、利于 SEO 与无障碍 | `index.html` |
| CSS 变量 | 在 `:root` 定义 `--color-primary`、`--radius`、`--shadow-*` 等，统一换肤只需改一处 | `css/style.css` 顶部 |
| Flexbox / Grid | 导航用 Flex 布局；景点卡片用 `grid-template-columns: repeat(3, 1fr)` 网格 | `css/style.css` |
| 响应式 | `@media (max-width: 768px)` 下：卡片变单列、导航折叠成汉堡菜单 | `css/style.css` 末尾 |
| 轮播图 | 自动播放 + 前后切换 + 圆点 + 悬停暂停 + 触摸滑动，用 `setInterval` + `class` 切换实现 | `js/main.js` `initCarousel()` |
| 分类筛选 | 事件委托监听筛选按钮，按 `data-filter` 匹配景点数据，动态重渲染卡片 | `js/main.js` `initFilter()` |
| 模态弹窗 | 点击「查看详情」打开，支持关闭按钮 / 点击遮罩 / ESC 三种关闭方式 | `js/main.js` `initModal()` |
| 本地存储 | 留言板、心愿单用 `localStorage` 持久化，刷新页面数据不丢失 | `js/main.js` `initMessages()` `initWishlist()` |

**可以主动展示的加分项**（体现工程素养）：

- **XSS 防护**：留言内容渲染前用 `escapeHTML()` 转义，防止用户输入 HTML 造成注入；
- **图片兜底**：Unsplash 外链失效时自动替换为内置 SVG 占位图，页面不会出现裂图；
- **数据驱动渲染**：景点数据集中在 `ATTRACTIONS` 数组，卡片由 JS 渲染，扩展景点只需加一条数据；
- **事件委托**：动态生成的卡片用事件委托监听，性能更好、代码更简洁。

## 四、功能演示顺序（照着点，配合讲解）

按下面的顺序演示，每个功能「先说一句——再操作」，节奏最稳：

### ① 轮播图（首页顶部）
- **操作**：等待 5 秒看自动切换 → 点左右箭头 → 点底部圆点跳转 → 鼠标悬停观察暂停 → 手机模拟器上左右滑动。
- **话术**：「首页轮播图支持自动播放和手动切换，悬停会暂停，移动端还支持手势滑动。」

### ② 景点分类筛选
- **操作**：点「自然风光 / 历史文化 / 城市地标 / 美食打卡 / 全部」几个按钮，观察卡片过滤。
- **话术**：「筛选通过事件委托实现，点击按钮按分类过滤景点卡片，DOM 会动态切换。」

### ③ 景点详情弹窗
- **操作**：点任意卡片「查看详情」→ 展示大图、评分、标签、简介 → 点「加入心愿单」→ 按 ESC 或点遮罩关闭。
- **话术**：「点击详情弹出模态框，支持三种关闭方式，还能在弹窗里直接收藏到心愿单。」

### ④ 留言板（持久化）
- **操作**：填昵称 + 留言 → 发布 → **刷新页面** → 留言还在；点「删除」移除。
- **话术**：「留言通过 localStorage 持久化，刷新页面数据也不会丢。」

### ⑤ 心愿单
- **操作**：回卡片点右上角 ♡ → 右侧「我的心愿单」出现该景点、计数 +1 → 点「移除」清掉。
- **话术**：「心愿单同样用 localStorage 存储，收藏的景点会同步显示在右侧面板。」

### ⑥ 响应式（可选，用浏览器开发者工具）
- **操作**：按 F12 → 切到手机尺寸（<768px）→ 导航变成汉堡菜单、卡片变单列。
- **话术**：「通过媒体查询做了响应式适配，移动端也能正常浏览。」

## 五、常见提问预判 + 参考回答

**Q1：为什么不用框架，而用原生 JS？**
> 课程要求先夯实基础，原生实现能让我更清楚 DOM 操作和事件机制的本质；而且项目规模不大，原生更轻量、无构建成本，直接部署即可运行。

**Q2：localStorage 的数据存在哪？刷新为什么会保留？**
> 存在浏览器本地（同源），以 JSON 字符串形式存储。我用 `JSON.stringify` 写入、`JSON.parse` 读取，并封装了 `load/save` 两个工具函数，异常读取时返回默认值兜底。

**Q3：轮播图是怎么实现的？**
> 结构上所有 slide 绝对定位叠在一起，通过切换 `active` 类配合 CSS `opacity` 过渡实现淡入淡出；JS 用 `setInterval` 每 5 秒切换到下一张，并用取模运算 `(current + 1) % length` 实现无缝循环；悬停时 `clearInterval` 暂停，移出后恢复。

**Q4：分类筛选的性能怎么样？如果景点很多会卡吗？**
> 每次筛选会重新渲染卡片列表，对于当前 9 个景点完全够用。若数据量大，可以优化为只切换已有卡片的 `display` 类，减少 DOM 重绘。

**Q5：图片为什么用外链？会不会失效？**
> 先用 Unsplash 免版权外链便于演示，并配置了规范的 `alt` 描述和 JS 兜底图。正式上线时会替换为 `images/` 目录下的本地图片，代码里已预留好替换位置。

**Q6：页面是怎么部署上线的？**
> 纯静态结构，推到 Gitee 仓库后开启 Gitee Pages，即可生成在线访问地址；本地也可直接双击或起一个静态服务器预览。
